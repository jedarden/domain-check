§6 SIGNALS SENT TO THE PROCESS
================================================================================

Mechanism: kernel memory-cgroup OOM killer → **SIGKILL** — uncatchable,
unrecorded by shell exit conventions, which is why needle's `agent.completed`
carries `exit_code = -1` (its unrecorded-signal SENTINEL; never a signal
number, never a name). The kernel's own "Killed process" lines ARE the
SIGKILL records (§2).

First-hand bf-4k2ws census, re-derived this session from the worker log
(UTC) — byte-exact against canon README §2:

  62 attempts, 2026-08-13 02:01–07:17Z:
    exit −1 (SIGKILL)  × 55   ← the storm
    exit 124 (600 s cap) × 5
    exit 0 (success)   × 2
  kill instants: 2026-08-13T02:03:33.620221603Z → 2026-08-13T07:03:53.920907594Z
  kill durations: min 123,571 ms · median 252,874 ms · max 528,854 ms

For scale, the same worker logged 395 `agent.completed` events that day
across ALL beads: 344 × −1, 22 × 124, 18 × 0, 11 × 1 — Aug-13 was a
whole-fleet kill day, of which bf-4k2ws's 55 were the largest single share.

Ruled out, first-hand: SIGHUP/SIGTERM — zero kernel kill text matching
SIGHUP/SIGTERM anywhere in the readable journal, and zero exit-129 events
(the code a process reports when it dies of SIGHUP/SIGTERM). This is the
falsification of the superseded August "SIGHUP-cascade" framing.

Coredumps: none for any agent kill — SIGKILL produces no core.
`coredumpctl` / /var/lib/systemd/coredump hold only unrelated entries

suite's negative tests; and ONE git core):

  `git rebase --no-autostash --onto 0f5a1be …`
  → 12 days AFTER the storm, a different failure class entirely (SIGBUS, not
  OOM); documented here only so it is never conflated with bf-4k2ws.
